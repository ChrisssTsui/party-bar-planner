# Party Bar Planner

将用户配方整理为 [输入规范](references/input-format.md) 中的 JSON，然后调用本目录 `scripts/planner.py`。确定性脚本负责校验、分杯、单位换算、合并、采购取整、成本与 HTML 渲染；不要用模型心算替代。

## 工作流程

1. 核对配方的名称、原料、单杯用量与单位、做法、装饰、杯型、含酒精选项。保留原配方，不自行修改口味。以稳定原料 ID 区分酒款、规格与椰奶/椰乳/椰子水；仅通过显式 `aliases` 合并名称。
2. 分开记录人数与杯数。只有人数时简短询问：“每位各喝哪些款、各几杯，或总共做几杯、各款比例是多少？”可草拟待确认计划，但确认前不生成最终采购单。
3. 明确库存、包装规格与价格、单一币种；未知价格用 `null`，不补零、不换汇。半个水果可用 `0.5 个`；一把冰需确认计量，质量与体积不互换。若没有包装信息，先补齐后执行。
4. 确认余量、装饰损耗率及分别适用哪些配方的摇和/搅拌冰、出杯冰规则。未给冰规则可省略，脚本输出待确认项，提醒采购单不包含这部分冰。
5. 仅对有依据可预混的原料设置 `stage: premix`；不确定用 `uncertain`。汽水、冰、鲜切装饰设 `serving_only: true`，对应配方行用 `serve`。不承诺保存期限。装饰若需要采购，必须同时作为 `role: garnish` 原料行列入，文字装饰说明不参与数量计算。
6. 保存本地输入，运行：

   ```sh
   python3 /path/to/party-bar-planner/scripts/planner.py input.json --out output
   ```

   输出目录以 `bar-guide.md` 为主交付：完整单杯配方、合并总材料量、逐款准备工作与当晚逐杯出酒流程。另含 `shopping.md`、`shopping.csv`、`costs.csv`、`batches.md`、`menu.html`、`summary.json`；同名生成文件会覆盖，选择新的输出目录可保留旧结果。输入不会修改。
7. 检查错误/待确认项和成本完整性。打开 HTML，检查打印预览；只有实际渲染后才声称 PDF/PNG 或 A4 布局通过。项目的可选 `tools/render_menu.cjs` 可在有 Playwright 与 Chrome 时导出；skill 本体不依赖它。

最终先交付 `bar-guide.md`，让用户能直接照着备料和出酒，不要只给文件列表或成本摘要。检查每杯的全部用量、做法、装饰、杯型，以及总材料和出酒流程是否完整；出酒流程沿用原做法，不自行猜测添加顺序。酒单不显示内部成本。将操作手册、采购和备料文件与对客酒单分别交付。所有处理在本地，无网络、付费 API 或购买操作。自然语言转录存在歧义时先询问，不能把待确认值伪装为精确事实。
